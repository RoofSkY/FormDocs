# 설치 가이드 (개발 담당자)

처음 한 번만 하면 됩니다. 설치 뒤에는 관리자가 Google 문서와 시트만으로 신청서를 운영합니다.

## 준비물

- 웹앱을 배포할 Google 계정 1개
  - 제출 문서는 이 계정의 Drive에 저장됩니다.
  - 양식 문서와 저장 폴더는 이 계정이 열 수 있어야 합니다.
- 이 저장소의 `src/` 파일 10개: 스크립트 6개(`Code.gs`, `Form.gs`, `Document.gs`, `Setup.gs`, `Util.gs`, `config.gs`), HTML 3개(`index.html`, `stylesheet.html`, `javascript.html`), `appsscript.json`

## 1. Apps Script 프로젝트 만들기

1. [script.google.com](https://script.google.com)에서 **새 프로젝트**를 만듭니다.
2. 기본 `Code.gs` 내용을 지우고 `src/Code.gs` 내용을 붙여 넣습니다.
3. **파일 추가(+) → 스크립트**로 아래 파일을 하나씩 만들고 같은 이름의 `src/` 파일 내용을 붙여 넣습니다.

   | 만들 이름 | 붙여 넣을 파일 |
   | --- | --- |
   | `Form` | `src/Form.gs` |
   | `Document` | `src/Document.gs` |
   | `Setup` | `src/Setup.gs` |
   | `Util` | `src/Util.gs` |
   | `config` | `src/config.gs` |

4. **파일 추가(+) → HTML**로 아래 파일을 만들고 붙여 넣습니다.

   | 만들 이름 | 붙여 넣을 파일 |
   | --- | --- |
   | `index` | `src/index.html` |
   | `stylesheet` | `src/stylesheet.html` |
   | `javascript` | `src/javascript.html` |

   - HTML 파일 이름은 반드시 위와 같아야 합니다. 코드가 이 이름으로 화면을 열고 끼워 넣습니다.
   - 편집기 왼쪽 파일 목록에 스크립트 6개와 HTML 3개가 모두 있는지 확인합니다. **하나라도 빠지면** 그 기능을 처음 쓸 때 `… is not defined` 오류가 납니다.
5. **프로젝트 설정(톱니바퀴) → "편집기에서 'appsscript.json' 매니페스트 파일 표시"**를 켭니다.
   그다음 `appsscript.json` 내용을 `src/appsscript.json`으로 바꿉니다.
6. 저장합니다.

## 2. `setup` 실행

1. 편집기 위쪽 함수 목록에서 **`setup`**을 고르고 **실행**을 누릅니다.
2. 처음 실행하면 권한 승인 창이 뜹니다. Drive·문서·스프레드시트 권한을 허용합니다.
3. 실행이 끝나면 내 드라이브에 다음이 만들어집니다.

```text
신청서 웹앱/
├─ 신청서 템플릿 시트      ('양식목록' 탭, '사용법' 탭)
├─ 양식 문서/
│   └─ [양식] 예시문서   (자리표시자 쓰는 법을 모두 담은 연습용 예시)
└─ 제출 문서/              (기본 저장 폴더)
```

4. **실행 로그**에 다음 두 값이 나옵니다.
   - `config.gs의 TEMPLATE_SPREADSHEET_ID에 붙여 넣으세요: …`
   - `config.gs의 DEFAULT_FOLDER_ID에 붙여 넣으세요: …`

> `setup`은 여러 번 실행해도 안전합니다. 다시 실행하면 기존 `양식목록` 탭과 양식 문서는 그대로 두고 `사용법` 탭만 새로 작성합니다.
> `TEMPLATE_SPREADSHEET_ID`가 이미 있으면 그 시트를 씁니다. `DEFAULT_FOLDER_ID`가 이미 있으면 `제출 문서` 폴더를 만들지 않습니다.

## 3. `config.gs` 설정

로그에 나온 ID를 붙여 넣고 저장합니다. 시트나 폴더의 주소 전체를 붙여 넣어도 됩니다.

```js
const TEMPLATE_SPREADSHEET_ID = '1AbC...';
const DEFAULT_FOLDER_ID = '1XyZ...';
```

### 설정 항목 전체

| 상수 | 기본값 | 설명 |
| --- | --- | --- |
| `TEMPLATE_SPREADSHEET_ID` | `''` | 템플릿 시트 ID. **꼭 넣어야 합니다.** |
| `FORM_LIST_SHEET_NAME` | `'양식목록'` | 신청서 목록 탭 이름 |
| `GUIDE_SHEET_NAME` | `'사용법'` | 관리자용 사용법 탭 이름 (`setup` 때 새로 작성) |
| `CACHE_SECONDS` | `300` | 템플릿 시트·양식 문서 캐시 시간(초). `0`이면 캐시하지 않음, 최대 `21600` |
| `DEFAULT_FOLDER_ID` | `''` | 기본 저장 폴더. 비우면 배포 계정의 내 드라이브 맨 위에 저장 |
| `DEFAULT_FILE_NAME` | `'{{form_name}}_{{submitted_at}}'` | `양식목록`의 `파일이름`이 비었을 때 쓰는 이름 규칙 |
| `APP_TITLE` | `'신청서'` | 신청서 목록 화면 제목 |
| `SHOW_DOC_LINK` | `true` | 제출 완료 화면에 저장된 문서 링크를 보여 줄지 여부 |
| `DATE_FORMAT` | `'yyyy-MM-dd'` | `{{date}}` 값의 형식 |
| `DATETIME_FORMAT` | `'yyyy-MM-dd HH:mm'` | `{{submitted_at}}` 값의 형식 |
| `MAX_TEXT_LENGTH` | `5000` | `text` 유형 최대 글자 수 |
| `MAX_SIGNATURE_BYTES` | `1000000` | 서명 그림 최대 크기(바이트) |
| `SIGNATURE_MAX_WIDTH` | `160` | 결과 문서 속 서명 그림 최대 너비(픽셀) |
| `SIGNATURE_MAX_HEIGHT` | `60` | 결과 문서 속 서명 그림 최대 높이(픽셀) |

> `SHOW_DOC_LINK`: 문서는 배포 계정의 Drive에 저장됩니다. 그래서 권한이 없는 사용자는 링크를 눌러도 문서를 열 수 없습니다.

## 4. 웹 앱 배포

1. **배포 → 새 배포 → 유형 선택(톱니바퀴) → 웹 앱**을 고릅니다.
2. 다음과 같이 정합니다.
   - **다음 사용자 인증 정보로 실행**: 나 (배포 계정)
   - **액세스 권한이 있는 사용자**: **모든 사용자**
3. **배포**를 누르고 웹 앱 URL(`…/exec`)을 복사합니다.

이 프로젝트의 운영 정책은 **실행: 나 / 액세스: 모든 사용자**입니다. 보호자가 Google 계정 없이도 작성할 수 있게 하기 위해서입니다.
`appsscript.json`에도 같은 값(`"executeAs": "USER_DEPLOYING"`, `"access": "ANYONE_ANONYMOUS"`)이 들어 있습니다.

이 설정에서 알아 둘 점:

- 주소를 아는 사람은 누구나 로그인 없이 신청서를 열고 제출할 수 있습니다. 주소는 필요한 사람에게만 알려 주세요.
- 제출한 사람의 이메일을 알 수 없으므로 `{{submitter}}`는 항상 비어 있습니다. 누가 제출했는지는 `{{성명*}}`처럼 입력 칸으로 받으세요.
- 문서는 배포 계정 권한으로 만들어지므로, 사용자에게 양식 문서나 저장 폴더를 공유할 필요가 없습니다.

> 액세스 권한을 바꿀 때는 운영 책임자와 먼저 확인하세요. 다른 선택지:
> - **Google 계정이 있는 모든 사용자**: 로그인이 필요합니다. 같은 도메인 사용자라면 `{{submitter}}`에 이메일이 들어갈 수 있습니다.
> - **나만**: 배포 계정만 열 수 있습니다. 시험용입니다.

## 5. 점검

웹앱 주소 끝에 `?check=1`을 붙여 엽니다.

```text
https://script.google.com/macros/s/…/exec?check=1
```

예시 양식이 **정상**으로 나오면 설치가 끝난 것입니다. 오류가 나오면 [문제 해결](troubleshooting.md)을 참고하세요.

## 예시 문서 다시 만들기

예시 문서(`[양식] 예시문서`)를 지웠거나 고쳐서 처음 상태로 되돌리고 싶을 때는 편집기에서 **`resetSampleForms`**를 고르고 **실행**합니다. 배포 계정 본인만 실행할 수 있고, `TEMPLATE_SPREADSHEET_ID`가 설정되어 있어야 합니다.

- `신청서 웹앱/양식 문서` 폴더에 예시 문서를 새로 만듭니다.
- `양식목록`에 양식ID `example` 줄이 있으면 그 줄의 `양식문서` 주소만 새 문서로 바꿉니다. 없으면 줄을 추가합니다.
- 그 줄이 가리키던 예전 문서는 이름이 `[양식] 예시문서` 그대로일 때만 휴지통으로 옮깁니다. 이름을 바꾼 문서는 그대로 둡니다. (휴지통에서 30일 안에 되살릴 수 있습니다)
- 다른 양식 줄과 양식 문서는 건드리지 않습니다.
- 끝나면 실행 로그에 새 문서 주소가 나옵니다. `?check=1`로 점검하세요.

## 코드를 고친 뒤 반영하기

| 바꾼 것 | 반영 방법 |
| --- | --- |
| 양식 문서, `양식목록` 탭 | 배포 갱신이 필요 없습니다. ([관리자 가이드](admin-guide.md#고친-내용이-반영되는-때)) |
| `src/`의 `.gs`·`.html` 파일 | **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포** |

- `/exec` 주소는 배포 버전을 갱신해야 바뀝니다.
- 개발 중에는 **배포 → 배포 테스트**의 `/dev` 주소로 확인합니다. `/dev` 주소에는 저장 즉시 반영됩니다.
- 기능을 바꿨다면 `setup`을 다시 실행해 템플릿 시트의 `사용법` 탭을 갱신합니다. 매뉴얼(`README.md`, `doc/`)도 함께 고칩니다.

## 로그 확인

편집기 왼쪽 **실행** 메뉴에서 실행 기록과 `console.log` 내용을 봅니다.

- 제출 성공: `제출 완료: 양식=…, 문서=…, …ms`
- 제출 실패: `제출 실패: …` 또는 `제출 실패(설정 문제): …`
- 주민등록번호 같은 입력값은 로그에 남기지 않습니다.
